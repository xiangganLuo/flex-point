# 第0阶段技术设计方案（现有内核优化）

> 阶段定位：在推进插件 SPI 化之前，先修复现有 `flexpoint-core` 的关键一致性与健壮性问题，确保后续架构升级建立在稳定内核之上。

---

## 1. 设计目标

本阶段只做“内核纠偏”，不做新平台能力。

### 必达目标
1. 完成事件链路接线闭环（Builder -> EventBus -> EventPublisher）。
2. 收敛注册中心并发语义，避免读写一致性隐患。
3. 统一扩展点计数口径，保证治理数据准确。
4. 收敛调用异常传播与事件语义，提升可观测一致性。
5. 增强事件总线边界鲁棒性与配置可治理性。

### 非目标
- 不引入完整插件管理器。
- 不扩展多语言/平台化功能。
- 不做治理平台 UI。

---

## 2. 问题来源与约束

问题来源：`core` 对齐评审（`第一阶段（core 插件 SPI 化）/CORE_ALIGNMENT_REVIEW.md`）中识别的 P0/P1 项。

约束：
- 优先保持 API 兼容；
- 仅在必要处调整行为语义；
- 每项优化必须有测试与回归验证。

---

## 3. 优化项技术方案

## 3.1 事件总线统一接线（P0）

### 现状
`EventPublisher` 依赖静态 `EventBus`，但构建期接线责任不清晰。

### 方案
- 在 `FlexPointBuilder` 构建流程显式创建/接入 `EventBus`。
- 在 build 成功路径调用 `EventPublisher.setEventBus(...)`。
- 在框架关闭流程补充 `EventBus.shutdown()` 生命周期管理。

### 验收
- 所有核心事件都可稳定发布并被订阅处理。

---

## 3.2 注册中心并发一致性（P0）

### 现状
`ConcurrentHashMap + ArrayList + synchronized` 组合下，读写并发语义不够清晰。

### 方案
- value 容器改为并发友好结构（如 `CopyOnWriteArrayList`）或改为不可变快照返回。
- 明确 `getAllExtAbility` 的一致性语义（快照读取）。
- 增加并发注册/注销/读取压测与竞争检测。

### 验收
- 并发读写下无数据竞争告警、无可见性缺陷。

---

## 3.3 扩展点计数口径统一（P0）

### 现状
总数统计路径存在偏差风险。

### 方案
- 统一由 Registry 暴露 `getRegisteredCount()`。
- `FlexPoint` 仅使用统一口径，不再自行拼计数。
- 在文档中明确“总数”与“按类型数”口径定义。

### 验收
- 计数结果与实际注册数一致。

---

## 3.4 调用异常传播与事件语义（P1）

### 现状
反射调用异常的包装/透传语义边界不统一。

### 方案
- 规范异常处理：是否解包 `InvocationTargetException`，并形成统一策略。
- 明确事件语义边界：`INVOKE_FAIL` vs `INVOKE_EXCEPTION` 的触发条件。
- 增加异常场景契约测试。

### 验收
- 业务侧捕获行为可预测，监控事件语义一致。

---

## 3.5 事件总线健壮性与配置化（P1）

### 现状
边界输入鲁棒性与线程池配置治理能力不足。

### 方案
- 增加防御式空值与非法输入校验。
- 将线程池参数统一接入 `FlexPointConfig` 并支持覆盖。
- 增加关闭与异常场景测试。

### 验收
- 边界输入下无额外 NPE/状态泄漏问题。

---

## 4. 测试策略

### 单元测试
- 事件接线与生命周期
- 计数口径
- 异常语义
- 边界输入健壮性

### 集成测试
- Builder + EventBus + EventPublisher 全链路
- 并发注册/查询一致性

### 并发与回归
- 高并发下 registry 读写稳定性
- 旧 API 行为兼容回归

---

## 5. 阶段退出标准（DoD）

1. P0 项全部完成并通过测试。
2. P1 项至少完成异常语义与事件总线鲁棒性中的核心项。
3. 输出“第0阶段完成报告”，作为第一阶段（插件 SPI 化）启动门槛。
